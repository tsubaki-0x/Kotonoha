# Local repository audit and safe organization — 2026-11-09

Project: Kotonoha v3, C++20/CMake/SDL3 multi-game repository; School Days HQ
Windows L4 is the current validation target. Host: Windows. Git branch at
audit start: `kotonoha-v3-ruaneri-sync-transitions`, commit `7e8da269`.

This is a **local working-tree** organization, not a GitHub release or a
license review. Large ignored folders can contain commercial/private data.
Do **not** delete them merely because Git ignores them.

## 1. Diagnosis

- **766 tracked paths** in Git. Game and engine source are separated under
  `games/` and `lib/` already; moving them is unnecessary and dangerous.
- `build/`: approximately **17.8 GiB** in about 25,340 files at inventory time.
  This is not a disposable build cache: it includes active L4 releases,
  community handoff artifacts, personal save files and junctions to the
  original retail installation.
- `Android/`: approximately **2.0 GiB**; mostly build/dependency output.
  Android work is deferred, but source and historical debugging inputs remain.
- `games/school-days/docs/`: **29 dated documents** originally together,
  11 tracked and 18 untracked. Some older reports describe intermediate or
  superseded requirements and should not silently override newer decisions.
- `*.log`, `.pdb`, `.obj`, `.pch`, `.pyc` and screenshots account for many
  generated files. Not all are safe to remove during ongoing Windows L4 QA.
- The `.gitignore` had one concatenated negation in its `debug` exceptions.
  Its existing `.vscode` ignore overrides earlier per-file VS Code exceptions.

## 4. Future optional cleanup requiring explicit retention review

1. Review old `build/` QA trees *individually* after determining whether the
   original saves, crash dumps or trace logs are still needed. Never use
   `git clean -fdx`, `Remove-Item build -Recurse` or commands that follow
   reparse-point/junction targets.
2. If organizing the 11 tracked School Days documents into subdirectories,
   use **`git mv`**, maintain redirects or stable links for consumers and
   update `PORT_STATUS.md`, cross-references in the docs, and external links
   when possible. A dated file may be intentionally referenced by old QA.
3. Make a deliberate decision whether to version-share any `.vscode` files;
   current `.gitignore` deliberately excludes the folder.
4. Test after any **code/build-input** move: CMake configure/build, School
   Days LauncherTest, Display tests and full CTest. The present cleanup moves
   only non-runtime documentation and ignored QA captures.
